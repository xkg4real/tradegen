# TRADEGEN PR5 추가 설계 승인안

작성일: 2026-11-13. 상태: **설계 검토용 · 미구현**.

## 승인 요청 범위

정상적으로 탈락한 전략 후보 때문에 다른 후보의 검증·서명까지 중단되는 문제를 수정하는 추가 설계입니다. 이 대화에서 사용자가 제시한 최신 지침 5는 “별도의 task나 워크플로우가 필요하다면 사용자의 승인 (이 창에서 클릭하는 방식으로 할 것)을 받고 진행해주세요.”입니다. 기존 계획의 인증 결과 처리 범위를 확장하는 이 부분은 소유자 승인 후 구현합니다. 메인 세션이 승인 절차를 진행하며, PR4c·4d·4e의 기존 승인 작업은 계속합니다.

## 확인된 충돌

- 승인된 [설계 §14](https://github.com/xkg4real/tradegen/blob/971a5389208c85d34fdd6479c96580e9b8fcc68d/docs/superpowers/specs/2026-11-11-upbit-krw-universe-design.md)는 보유 종목의 소멸·평가 불가·마지막 청산 호가 부재로 탈락한 후보가 있어도 다른 후보는 계속 평가하도록 규정합니다.
- [PR5 구현 계획](https://github.com/xkg4real/tradegen/blob/971a5389208c85d34fdd6479c96580e9b8fcc68d/docs/superpowers/plans/2026-11-11-upbit-krw-universe-pr5-study.md)은 이러한 실패를 예외로 처리하면서 기존 연구 승인 절차는 변경하지 않도록 작성돼 있습니다.
- 현재 `study._select`는 후보 하나라도 평가 결과가 없으면 **모든 승인 요청 생성을 중단**합니다. `study_review.authenticate_study_selection`도 같은 예외에서 전체 검증을 중단합니다.
- 기존 `ValidationResult`에는 수익률·확률 등 완성된 수치가 필수입니다. 평가할 수 없었던 후보를 이 형식으로 채우면 근거 없는 수치를 만들게 됩니다.

## 제안하는 변경

1. 평가 및 승인 검증이 함께 사용하는 **후보별 결과 처리 함수**를 둡니다. 정상 평가 결과와 정당한 시장 사유로 중단된 실패 결과를 구분합니다.
2. 실패를 인정하기 **전에 해당 파일 전체의 입력 검증을 끝냅니다**. 등록, 프로토콜, 규칙, 기간, 모든 프레임·결정·해시를 검증합니다. 앞부분에서 정당한 탈락이 발생해도 뒤의 손상된 데이터를 숨길 수 없게 합니다.
3. 허용한 고정 실패 사유에만 별도 실패 기록을 만듭니다. 실패 전용 형식 식별자, 프로토콜·등록·전체 입력의 해시, 실패 사유·위치를 포함해 정해진 방식으로 해시합니다. 정상 결과 해시와 의미가 혼동되지 않도록 구분합니다.
4. **현재 schema-2 서명 문서의 전체 후보 목록과 원본 바이트 해시를 유지**합니다. 탈락한 후보도 반드시 포함하며, 실패 기록 해시를 그 후보의 증거 해시로 연결합니다. 원본에 공백 하나만 달라져도 기존 서명과 일치하지 않습니다.
5. 실제 평가기가 발급한 `ValidationResult`만 수치 비교·순위·승인 대상이 됩니다. 탈락 후보는 사유를 표시하고 제외합니다. 실패 후보의 수익률·확률을 만들거나 임의의 0으로 채우지 않습니다.
6. 누락·불완전·잘못된 형식·변조가 있는 파일은 **전체 후보군 검증을 거절**합니다. 벤치마크를 평가할 수 없으면 어떤 후보도 선발하지 않습니다. 외부 서명기의 형식·키·실거래 권한을 바꾸지 않습니다.

기술적으로 기존 schema-2 문서의 필드 구성을 유지할 수 있지만, 실패 후보 증거의 의미와 승인 검증 경로가 확장됩니다. 이것이 이번 추가 승인의 대상입니다.

## 변경 파일 및 완료 기준

- 예상 코드: `execution_launch/strategy.py`, `execution_launch/study.py`, `execution_launch/study_review.py`. `review_request.py`는 기존 형식으로 처리할 수 있으면 변경하지 않습니다. 추가 파일·형식 변경이 필요하면 먼저 설계를 다시 검토합니다.
- 예상 검증: `tests/launch_universe_study.py`, `tests/launch_study_review.py`; 필요한 경우 `tests/launch_review_request.py`.
- 완전한 후보군에서 **수학적 기준을 통과한 후보 + 정당하게 탈락한 후보**가 함께 있을 때, 전체 원본이 서명에 포함되고 통과 후보만 선발 가능해야 합니다. 검증에는 합성 데이터와 일회용 테스트 키만 사용합니다.
- 정당한 초기 탈락 뒤에 손상된 마지막 프레임·결정이 있으면 전체 거절해야 합니다. 실패 후보 원본 변경·후보 누락·승자 변경 후 서명 생략도 기존 서명으로 통과할 수 없어야 합니다.
- 모든 후보 탈락 및 벤치마크 실패는 선발 없음으로 끝나야 합니다. 실패 수치·확률을 만들지 않아야 합니다. 기존 고정 종목 평가와 PR13의 전체 후보 원본 검증 회귀 테스트를 유지해야 합니다.

## 별도로 처리할 기존 계약 준수 수정

다음 두 사항은 위 인증 결과 확장과 구분해 구현·검토합니다.

- **결정 시각:** 현재 계획은 계산 전 시각을 결정 시각으로 기록합니다. 실제 결정 계산 후 시각을 확인·기록하고, 다음 체결 시점까지 필요한 지연을 확보하지 못했으면 실패로 남깁니다. 계산 지연·시계 역행·정확한 경계 시각을 테스트합니다.
- **틱 규칙 수신 시각:** 슬롯 이후에 도착한 틱 규칙을 과거 슬롯의 주문 반올림에 사용하지 않도록, 수집 경계에서 수신 시각을 확인합니다. 정시 호가와 늦은 틱 규칙을 조합한 회귀 사례를 추가합니다.

별도 예정된 **호가 시계 허용 오차 1초 수정은 PR5 공통 `_book` 처리 추출 이후, 최종 코드 승인 전에** 적용합니다. 이 허용 오차를 늦게 수신한 데이터의 소급 사용 허용으로 해석하지 않습니다.

이 문서는 코드 설계 승인안입니다. 실제 연구 결과·성공 확률·실거래 활성화 또는 48시간 데이터 수집 완료를 뜻하지 않습니다.
