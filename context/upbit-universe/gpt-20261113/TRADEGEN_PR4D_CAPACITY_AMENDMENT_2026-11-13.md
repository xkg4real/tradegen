# TRADEGEN PR4d 기록 용량 추가 설계 승인안

작성일: 2026-11-13. 상태: **제안 · 미구현 · 소유자 승인 대기**.

## 확인된 문제

[설계 §12](https://github.com/xkg4real/tradegen/blob/971a5389208c85d34fdd6479c96580e9b8fcc68d/docs/superpowers/specs/2026-11-11-upbit-krw-universe-design.md)는 이력 한 행을 256 KiB 이하로 유지하면서, 커지면 플래그·티커 정보를 제외해 기록하고 매수를 차단하도록 정했습니다. 그러나 [PR4d 계획](https://github.com/xkg4real/tradegen/blob/971a5389208c85d34fdd6479c96580e9b8fcc68d/docs/superpowers/plans/2026-11-11-upbit-krw-universe-pr4d-driver-history.md)의 이 처리만으로는 한도를 지키지 못하는 입력이 있습니다.

- 합성 데이터의 **상장폐지 잔여 코인 1,500개**가 현재 계좌 수집기와 잔고·거래내역 대조 검증을 통과했습니다. 조회 수는 기본 제한 안의 1,522회였습니다.
- **128 KiB 호가 원본**도 현재 호가 파서와 슬롯 시각 검증을 통과했습니다.
- 후보는 두 종목뿐이고 임의의 긴 오류 문구도 없었습니다. 플래그·티커·매수 목록을 제외한 뒤에도 계획된 행은 **279,312바이트**로, 한도 **262,144바이트**보다 **17,168바이트** 컸습니다.
- 이는 실제 고객 계좌나 거래소에서 관측한 사례가 아니라, 현재 검증을 통과하는 입력으로 재현한 소프트웨어 용량 문제입니다. 그대로 구현하면 기록이 거부되어 해당 거래 구간이 종료될 수 있습니다.

## 제안하는 처리 순서

1. **현재 계획의 1차 대체 처리 유지:** 플래그와 티커는 `unavailable`, 매수 허용 목록은 빈 목록으로 기록하고 고정 사유 `HISTORY_ROW_SIZE_FALLBACK`을 남깁니다.
2. **그래도 크면 2차 대체 처리:** 호가 receipt도 `unavailable`로 기록합니다. `book=None`으로 해당 슬롯의 바·결정·연결 해시를 다시 계산하여, 사용할 수 없는 호가가 가격 근거나 주문 근거로 남지 않도록 합니다. 매수 허용 목록은 계속 비어 있습니다.
3. **계좌 근거는 끝까지 보존:** 모든 보유 코인의 수량·평가가격·평가시각·상장폐지 및 잔여 자산 표식, 계좌 기준값, 스냅샷 근거를 임의로 삭제하거나 줄이지 않습니다. 행 용량 한도도 늘리지 않습니다.
4. **계좌 근거만으로도 초과하면 명시적으로 거부:** 고정 용량 진단을 반환하고, journal에 추가하거나 독립 head 및 슬롯 상태를 변경하기 **전에** 중단합니다. 운영 안내에는 자동매매를 계속할 수 없다는 상태와 별도 검토가 필요한 자료 범위를 표시합니다. 진행 중 구간의 기록이 불가능하면 기존 누락 슬롯 종료·운영자 직접 종료 절차를 따릅니다.
5. **보장 문구 정정:** “크기 때문에 행이 거부되는 일은 없다”는 무조건적 약속을 철회합니다. 보존해야 하는 계좌·슬롯 근거가 정해진 기록 용량 안에 들어가는 것을 입력 허용 조건으로 명시합니다. 가능한 사전 준비 단계에서 확인하고, 매 슬롯에서도 확인합니다. 넘치는 자료는 자동 축약하지 않습니다.

위 사례는 2차 처리 후 104,252바이트가 되어 모든 계좌 근거를 유지한 채 기록할 수 있습니다. 호가를 제외한 슬롯에서는 자동 청산도 실행되지 않을 수 있으므로, 기록 연속성이 주문 실행 가능성을 뜻하지는 않습니다.

## 구현 범위와 검증

- 주 변경 범위는 PR4d의 `execution_launch/live_history.py`와 관련 이력·드라이버 테스트입니다. PR4e 연결 시 용량 거부를 누락 슬롯 종료 및 운영 안내에 전달합니다. 새 진단의 이름은 구현 전에 확정합니다.
- 검증: 1차 처리로 충분한 경우, 2차 처리가 필요한 경우, 보존 자료 자체가 초과한 경우를 각각 확인합니다.
- 2차 처리에서는 **매수 없음·호가 근거 없음·계좌 근거 보존**과 재시작 후 동일한 결정·해시를 검증합니다.
- 최종 용량 거부 시 **journal 원본·독립 head·슬롯 및 선택 상태가 그대로**여야 합니다. 행 크기 경계는 개행까지 포함해 확인합니다.
- 기존 고정 종목 프레임·슬롯의 golden digest와 기존 테스트를 유지합니다.

## 승인 대상과 진행 가능한 작업

승인 대상은 **호가를 제외하는 2차 처리와 유한한 기록 용량을 입력 조건으로 명시하는 계약 정정**입니다. 승인되기 전에는 이 추가 설계를 구현하지 않습니다. PR #33 병합 후 PR4d Task 1의 기존 승인된 기초 작업은 진행할 수 있습니다.

승인이 필요한 근거는 사용자의 최신 지침 5입니다: “별도의 task나 워크플로우가 필요하다면 사용자의 승인 (이 창에서 클릭하는 방식으로 할 것)을 받고 진행해주세요.” 이번 변경은 승인된 계획의 대체 처리와 보장 문구를 확장·정정하므로 메인 세션에서 그 절차를 진행합니다.

이 문서는 코드 설계 승인안이며 실제 API 호출, 전자서명, 거래 활성화 또는 주문 승인이 아닙니다.
