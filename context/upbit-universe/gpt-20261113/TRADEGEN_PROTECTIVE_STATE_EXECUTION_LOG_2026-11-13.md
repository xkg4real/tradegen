# TRADEGEN 보호 보유 P1 — 순수 상태 전이

2026-11-13. **상태 계산 모듈과 검증을 완료했다. 실제 주문·기존 driver·coordinator에 연결한 단계가 아니다.** 기한만으로 매도하지 않고 새 관리 승인을 요청한다는 사용자 결정은 재질문하지 않았다.

## 구현

- `execution_launch/protective_state.py`: 명시 정책·사건·관측·권한 사실에서 불변 상태와 후속 처리 의도만 계산한다. 파일·네트워크·시계 조회·서명·주문 호출은 없다.
- 기한·조회/계산/계좌/저장/설정 오류·재시작 자체로 매도 검토 의도를 만들지 않는다. 기한은 신규 진입 차단과 안정적인 ID의 관리 승인 요청을 만들며 기한이나 권한을 자동 연장하지 않는다.
- 실제 HOLD, 전략 판단 불가, 위험 조건은 확인됐으나 실행 불가한 상태를 구분한다. 독립적으로 유효한 전략 SELL 또는 기존 위험 조건이 있고 관련 자료·권한·기록·주문 조건을 모두 충족할 때만 `consider_reduce`를 낸다.
- 진입 중지와 감소 거래 허용을 분리한다. 기존 위험정책이 허용한 감소 거래를 새 일괄 halt 조건으로 막거나, 반대로 금지된 감소를 허용하지 않는다.
- 진입·감소·취소·감시의 권한과 만료를 분리한다. 재시작 복구나 관리 권한 갱신만으로 신규 진입을 다시 허용하지 않는다.
- 미처리 outbox·미체결/부분체결/UNKNOWN 매도는 추가 매도 검토와 신규 진입·재활성화를 막는다. 복구된 사실로 해소돼야 한다.
- 같은 사건과 사실의 중복은 효과를 다시 내지 않는다. 사건 재작성·순서 변경·정상 시계의 역행을 거절한다. 시계 오류 사건은 마지막 신뢰 시각을 보존해 잘못된 미래 시각 때문에 복구가 영구 차단되지 않게 한다.
- `close`는 관리 상태의 종료이며 보유 자산이 없거나 청산이 체결됐다는 주장이 아니다.

입력인 `AuthorityFacts`는 호출자가 제공하는 모형 자료다. 이를 만들었다고 전자서명·독립 검증·주문 권한이 발급되지 않는다. 상태의 `can_*` 값과 처리 의도 역시 실행 권한이 아니다. 기존 손실 하한·위험 한도를 계산하거나 변경하지 않는다. 범위는 Upbit 원화 현물이다.
