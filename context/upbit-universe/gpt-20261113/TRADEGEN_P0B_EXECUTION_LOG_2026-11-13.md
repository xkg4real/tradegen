# TRADEGEN 실제 이력 무손실 저장 연결 — P0b

기록 시점: 2026-11-13. 코드 `a0b28d0fc0fee4a359f833f91a7c0f572777481e`, PR34에 push 완료. **핵심 검사와 전체 회귀의 실행 가능한 검사를 통과했다. 전체 개발·Windows 배포·실거래 활성화 완료가 아니다.**

## 변경한 내용

- 새 universe 이력 v3에 명시적 저장 정책을 연결했다. 정책 해시 → protocol → driver identity → 슬롯 자료의 순서로 결합하며, 과거 서명을 변경된 코드의 승인으로 재사용하지 않는다.
- 큰 논리 기록은 원본 전체를 객체에 보존하고 작은 참조 행을 journal에 기록한다. 정상 호가·모든 보유 내역·정상 flags/tickers/allow를 용량 때문에 버리는 fallback을 새 기록에서 제거했다.
- 객체 잠금 안에서 실제 사용량과 임시·최종 파일의 동시 공간을 계산한다. 미참조 파일도 새 쓰기의 예산에 포함한다. journal은 개행을 포함한 별도 한도를 지킨다. 한도는 명시적으로 입력하며 임의 운영 기본값을 선택하지 않았다.
- journal 확정 전 전체 객체를 검증하고, 독립 head도 참조·문맥·내부 자료 형식을 검증한다. 재시작 시 계좌·호가·보유·전략 결정을 재생한다. 중단된 쓰기를 자동 채택·삭제·복구하지 않는다.
- provider/verifier는 전체 확정 prefix를 다시 검사하며 검증 중 시간이 흘러 만료되거나 시계가 역행하면 거절한다. 검증 과정은 새로운 메모리 상태를 채택하지 않는다.
- 무관한 orphan/pending 때문에 정상 기존 참조의 조회까지 막지 않는다. 새 기록의 용량 초과·불완전 쓰기는 거절한다.
- coordinator, 소유자 초기화 CLI, rehearsal에 동일한 명시 정책을 전달한다. 독립 서명기와 앱의 코드 검증 파일 목록을 함께 갱신했다.
- 기존 fixed v1·과거 universe v2의 wire bytes와 생략된 선택 필드의 digest는 유지한다. 새 universe 창은 v3 정책을 요구하며, 과거 identity로 변경된 코드를 재개하지 못한다.

## 독립 검토 후 보완

내부 자료 형식 검증 전에 head가 전진하는 경계, 너무 작은 초기 journal 예산을 거절하기 전에 디렉터리가 생기는 경계, 생성 후 변경된 frozen 정책의 해시 재검증을 보완했다. 입력 형식은 저장 전에도 검사해 잘못된 입력이 창을 복구 대기 상태로 만들지 않게 했다. codec은 실제 직렬화된 bytes도 다시 검사하고 용량 오류의 진단을 보존한다.

## 검증

- 최종 핵심 회귀: **213 PASS / 0 FAIL / 0 NOT_RUN**, 20.303초.
- Python/YAML fingerprint: `308ff5e1097a6e3960b83bae5ab723c61d453cfdaffef1f61af7c8c4864dd98b`. 테스트 작업본과 전달 커밋이 일치한다.
- 전체 회귀: **2660 PASS / 0 FAIL / 135 NOT_RUN (전체 2795개; 환경 재시작 뒤 동일 소스의 나머지 검사를 재개)**. NOT_RUN은 기존 macro 전제 121개와 Windows 전용 14개다. 미실행을 통과로 계산하지 않는다. 같은 frozen 소스를 검사했으며 이전 PR34/P0a 결과를 재사용하지 않았다.
- 합성 계좌 1,500개 보유와 131,072바이트 정상 호가를 실제 collector → 저장 → 독립 head CAS → 재시작 경로에서 검사했다. 원래 한 행으로 직렬화하면 262,144바이트를 넘지만 v3 journal 참조는 2,048바이트 미만이며 전체 논리 자료와 원본 호가 bytes가 복원된다. 실제 계좌 장애 사례가 아니다.
- 실제 쓰기 순간의 peak bytes/개수와 journal 길이를 측정해 한도 직전·정확히 한도·한도 직후를 검사했다. 객체 손상·누락, 부분 journal 쓰기, head 갱신 실패, 초기 예산 거부, 정책 변경, 검증 중 시간 만료·역행을 포함한다.
- 19개 키 이름을 `<unset>`으로 고정하고 fake 입력·격리 홈을 사용했다. 소스와 실제 홈의 파일 메타데이터는 변경되지 않았고 QA 산출물은 복원했다. 실제 키·원본 owner log·거래소 API·전자서명·활성화·주문은 사용하지 않았다.
- 최초 검사에서 테스트 시계 설정 7건이 실패했고 수정 후 통과했다. 최초 실패 결과를 숨기거나 통과로 계산하지 않는다. Windows 전용 검사는 Linux 통과로 대체하지 않는다.
