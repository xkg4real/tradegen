## 재현 환경과 원시 증거

- Linux x86-64, CPython 3.13.16, Debian g++ 14.2.0-19. C++20과 C++17을 서로 다른 작업 사본에서 새로 빌드해 바이너리 해시가 일치하는지 확인했다. 동일한 실행 파일을 확인할 수 없는 환경은 Python 또는 NumPy 경로를 사용한다.
- C++20 SHA-256은 `66967ba825a69761668e82e09117ebeb73aa7f416e1bb18767d69eb5c346a7ce`, C++17 SHA-256은 `5422b5743c8943e44edaf683e66220b8db3cd81c8f929f09d8bb21539b13a510`이다.
- `0e76163`에서 소유자·외부 서명기·브로커의 파일 141개 경로와 해시가 일치했다. 브로커는 하드링크된 Cloud 패키지 메타데이터를 거절했다. 동일한 설치본의 METADATA와 RECORD를 독립 파일로 복사한 임시 경로로 브로커를 재검증했다. 실제 운영 환경의 무결성·서명은 별도 확인 대상이다.
- 원본 성능 로그의 HP-6 10,000 경로 표기는 실제 2,000 경로 픽스처와 달랐다. 수정된 속도 검사는 10,000 경로, 10일 시나리오를 사용한다. 같은 벤치마크 입력에서 계산 결과 12개 열 각각에 실제로 10,000개 경로가 기록된 것을 별도로 확인했다. 거래소 왕복·주문 체결 지연은 이 측정에 포함되지 않는다.
- 전수 실행은 저장소의 suite registry를 사용한다. launch는 순서대로 열거한 전체 케이스를 4개로 나누어 실행하고 통합 시 이름 중복·누락, 레지스트리 해시와 합계를 검사했다. 1,803개 검사 이름의 SHA-256은 `65916ba71c2b76f1b362eb72726505a10376ee32b589c014ec51554476273215`이다. `qa/acceptance_results.json`과 동결 연구 경로는 원본 main과 바이트 변경이 없다.

아래 명령은 고정 커밋의 프로젝트 가상환경에서, 테스트 계정 상태와 가짜 전송을 사용하는 환경에서 실행한다. 일부 검사 실행기는 Windows 전용 테스트가 남아 있어도 종료 코드가 0일 수 있으므로 PASS·FAIL·NOT_RUN 집계를 확인한다.

```bash
python -B native/tradegen_fast/build_native.py
python -B -m qlib_lab._accel.build_accel
python -B -m tests.launch_acceptance
python -B -m tests.control_acceptance
python -B -m tests.compliance_acceptance
python -B -m tests.accounts_acceptance
python -B -m tests.execution_acceptance
python -B -m tests.odds_acceptance odds_guards
python -B -m tests.native_cpp_acceptance
python -B -m tests.live_controlled_acceptance
python -B -m tests.qlib_lab_acceptance
QLIB_LAB_DISABLE_ACCEL=1 python -B -m tests.qlib_lab_acceptance
python -B -m unittest discover -s tools/research -p "test_*.py"
```

Cloud 실행 기록의 `qa-final/commit.txt`은 전수 실행 커밋, `qa-final/coverage-adjusted.json`은 사례별 재검증·미실행 사유, `qa-final/launch-0.json`부터 `launch-3.json`까지는 launch 레지스트리와 개별 결과를 담는다. `qa-native-check`의 `deployment_compat.log`, `renewal_surfaces.log`, `revocation_windows_wiring.log` 및 `broker_singlelink.log`에서 수정 후 결과를 대조할 수 있다.

### Linux 오프라인 계산 시간

첫 실행에서 HP-1 평균은 C++ 74.55ms, Python 54.44ms였고 속도 조건을 실패했다. 당시 C++ 5회를 먼저 측정하고 Python 2회를 이어서 측정했으며, 다른 검증 작업도 진행 중이었다. 속도 비교가 첫 조건에서 중단돼 당시 HP-3·HP-6 시간은 기록되지 않았다.

두 번째 실행은 동일한 런타임에서 측정 절차만 변경한 `d8f518186d3a9f6d41a2ef90c936264cd8b90713`에서 수행했다. 같은 Linux 호스트에서 다른 검증 작업을 마친 뒤 백엔드별 1회 예열하고, 업무별로 C++ 먼저와 Python 먼저를 번갈아 6쌍 측정했다. 각 구현의 중앙값을 비교했고 세 종류 모두 C++이 빨라야 통과한다는 조건을 유지했다. 전체 native suite 결과는 통과 9건 · 실패 0건 · 미실행 0건이다.
