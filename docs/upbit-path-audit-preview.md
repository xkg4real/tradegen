# Upbit 체결과 1분봉의 오프라인 대조

`execution_accounts.path_checks`와 `execution_accounts.candle_audit`는 보관한 원본 응답을 재생한다. 검토자는 공개 체결 목록, 계좌의 주문별 체결과 1분봉 사이의 차이를 확인할 수 있다. 이 단계의 결과는 조회 및 연구용이며 주문 권한이 없다.

## 체결 대조

`own_fill_findings(walk, orders, account_scope=scope, expected_order_ids=reviewed_ids)`에 계좌 원장에서 확인한 해당 종목의 전체 주문 ID 집합, 원본 응답을 포함한 `OrderFillsResult` 튜플과 `TradeWindowResult`를 전달한다. 원래 수집에 체결별 수수료 증거나 앵커 ID가 사용됐다면 같은 입력을 제공한다. 재생한 바이트·계좌·요청·커서·파생 기록이 일치해야 한다.

검사 구간의 시작과 끝은 공개 체결의 밀리초 정밀도에 맞춘다. 시작은 포함하고 끝은 제외한다. 경계가 한 밀리초 안을 가르면 어느 쪽 체결인지 확인할 수 없으므로 해당 조회를 다시 구성해야 한다. 공개 체결 한 건은 밀리초·가격·수량이 같은 계좌 체결 한 건에만 대응한다. 조건이 같은 계좌 체결이 여러 건이면 어느 주문인지 추정하지 않고 부족한 건수(`occurrences`)를 남긴다. 체결되지 않은 자기체결방지 수량은 검사 대상에서 빠진다. 매수·매도 표시는 거래소 측 의미를 확인할 별도 짝지은 관측이 필요하다. `ticker_findings`는 같은 원본에서 재현한 티커 불일치를 반환한다.

## 뒤늦게 받는 1분봉

`audit_minutes`에 같은 계좌·종목의 연속된 체결 구간들과 첫 UTC 정각 분, 각 분에 대한 원본 응답을 시간순으로 전달한다. 조회는 해당 분 종료 UTC 시각을 배타적 상한으로 한 1분봉 한 건이어야 한다. 여러 짧은 체결 구간을 한 분으로 합치거나 긴 구간의 여러 분을 검사할 수 있다. 큰 기록은 완전한 UTC 분 경계에서 나누어 처리한다.

별도로 신뢰할 수 있는 검증기를 `verify_finality(challenge, receipt)`에 주입한다. 검증기는 실제 측정 근거와 출처를 인증하고, 이 계좌·종목·분·응답·체결 기록에 묶인 확정 시각과 검증 근거를 반환한다. `tools/research/upbit_trade_probe.py`의 두 안정된 관측만으로 확정 시각을 정할 수 없다. 이 변경은 운영 검증기나 실측 확정 지연값을 제공하지 않는다.

| 결과 | 해석 |
|---|---|
| `CHECKED` | 확정 이후 읽은 원본과 전 구간 체결을 대조했다. 발견 사항이 있다면 그 근거 해시를 함께 보존한다. |
| `MISSING_CANDLE_RECEIPT` | 요청 분의 캡처가 없다. |
| `FINALITY_UNVERIFIED` | 독립적으로 확인된 확정 근거가 필요하다. |
| `NEED_LATER_CAPTURE` | 해당 응답을 확정 시각보다 일찍 읽었다. 확정 이후 캡처가 필요하다. |

봉의 저가가 경로보다 낮거나 고가가 경로보다 높으면 재검토 가격으로 그 봉의 **저가**를 기록한다. 고가는 최고 평가액을 올리는 입력이 되지 않는다. 지정한 종료 시각 직전의 가장 최근 봉 한 건을 요청했을 때 빈 응답이거나 이전 분의 봉이면, 확정 근거와 수신·서버 시각 검사를 통과한 뒤 해당 분의 봉이 없었다고 판정한다. 그 분에 경로 체결이 있다면 `CANDLE_MINUTE`의 가격은 `None`이다. 경로 체결도 없으면 발견 사항 없이 `CHECKED`로 기록한다. 실시간 분봉 수집, 운영 검증기, 알림과 거래 진입 보류의 연결은 후속 과업이다.
