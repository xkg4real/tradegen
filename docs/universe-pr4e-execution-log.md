# TRADEGEN PR4e — 유니버스 실행 연결 검증

2026-11-13. 유니버스의 기록된 관측·후보·호가·계좌 상태를 모의운영 Runner와 Coordinator에 연결했다. 실계좌 활성화나 실제 주문을 수행한 결과가 아니다.

## 변경

- 매수 허용 목록과 해당 관측에 결합된 준비 결과를 Runner 내부 잠금에서 검증한다. 종목 전환에는 같은 계좌의 최신 관측과 기존 주문 상태가 필요하다. 매수 제한과 기존 매도 경로를 구분한다.
- Coordinator가 선택 종목의 규칙·호가·보유·시장 사건을 실제 v3 이력에 보존하고, 기록한 허용 목록으로 실행한다. 저장 거절을 정상 호가의 누락으로 바꿔 재시도하지 않는다.
- 준비 관측은 정확히 한 번 읽는다. 가격 자료 수집 후 관측과 현재 시각을 다시 확인하여 지연·서울 날짜 변경·시계 역행을 거절한다. 실패한 과거 준비 결과를 재사용하지 않는다.
- 보유 종목의 거래 중단과 규칙 조회 실패를 구분한다. 알려진 상장 폐지 사건은 알림·해제 처리 실패 시에도 새 tick을 차단한다. 다른 종목의 비활성을 보유 종목의 소멸로 해석하지 않는다.
- 알림은 순서 보존 큐에서 처리하여 느린 알림이 기록·감시를 지연시키지 않게 했다. 실패 상태는 숨기지 않는다.
- 기존 고정 종목 창은 24시간, 명시적 유니버스 창은 72시간으로 구분하며 실제 조립 시 다시 검사한다. 리허설에 없는 준비 provider를 있다고 간주하지 않는다.

- 런타임 커밋: `a772a24073ffb523ff7fa8d1e030398eaf56227a`.
- Python/YAML fingerprint: `b80c7edc057f9288a3b41507c7dfeeef29a0706c7f642b7482a43407b4d6b33b`.
- 전체 등록 검사 **2,907건: 2,772 PASS / 0 FAIL / 135 NOT_RUN**, 단일 연속 프로세스, **1240.435초**. 실행하지 않은 검사를 통과로 세지 않았다.
- 이전 2,819개 검사 ID와 상태를 모두 보존했다. 추가 88개는 전부 PASS다.
- 독립 회귀 9개도 별도로 PASS: 수집기 → Coordinator → 실제 객체 저장·v3 journal·독립 head CAS → 재시작 경로에서 합성 보유 1,500건과 131,072바이트 정상 호가를 보존했다. 바깥 참조는 2KiB 미만이고 논리 기록은 기존 256KiB 한도를 넘는다. 계좌·연구·주문 seam은 합성이므로 실제 권한·체결 입증이 아니다.
- 19개 KEYLESS 변수, 격리 홈, 가짜 transport를 사용했다. import 및 검사 목록 구성 전부터 종료까지 실제 홈 메타데이터와 소스가 변하지 않았고 QA 산출물을 복원했다. 실제 키·외부 거래소/증권사 API·주문은 사용하지 않았다.
- 개발 중 155 PASS 실행은 최종 수정과 겹쳐 source_unchanged=false였다. 최종 근거로 사용하지 않고 위 동결 소스의 전체 실행으로 대체했다.

## 남은 경계

현재 조립은 모의운영 전용이다. 실제 보유·체결을 연속 대조하는 운영 어댑터, 실제 자료 완전성·관리 권한 발급, controlled launcher, 소유자 승인과 활성화는 별도 작업이다. 기한 알림은 새 관리 승인을 요청하지만, 이 PR의 기존 고정 driver에는 종단 target=0 의미가 남아 있다. 기한만으로 매도하지 않는 동작은 별도 carry 버전에서 평가·서명·실행을 함께 바꾸고 검증해야 한다.

기존 손실 하한·위험 한도는 완화하지 않았다. 앱 실행만으로 자동매매 준비가 완료된 상태가 아니다. 법률, 세무, 투자 조언이 아니며 면허를 가진 자문가가 아니다.
