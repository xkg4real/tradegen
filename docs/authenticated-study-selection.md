# 서명된 검토를 연구 선택에 연결하기

`execution_launch.study select`는 수치 조건을 통과한 후보의 **서명 전 검토 요청**을 만듭니다.
이 단계의 `NO_QUALIFIED_MARKET`은 검토가 아직 인증되지 않았다는 뜻일 수도 있습니다.
`execution_launch.study_review select-reviewed`는 실제 소유자 서명과 현재 승인 상태를 확인한 뒤,
원래 정해 둔 순위 규칙으로 후보를 선택합니다. 선정 결과는 주문 권한이 아닙니다.

## 필요한 순서

1. 새 계획을 사전 등록·게시하고, 정한 기간의 관측을 누락 없이 수집합니다. 기존 자료를 새 전향 자료로
   바꾸거나 실패한 시행을 제거하지 않습니다. 48시간 계획은 실제 48시간의 관측이 필요합니다.
2. 현재 프로필로 기존 `study select`를 실행합니다. `--now`에 쓴 **원래 평가 시각**을 보관합니다.
   현재 거래 조건의 `asof`는 새 실제 관측으로 갱신할 수 있지만, 원본 출처와 비용·수량·틱·정책 등
   동결한 조건이 달라지면 기존 연구를 그대로 사용하지 않습니다.
3. 출력의 `review_requests` 배열에서 각 요청 객체를 별도의 비공개 JSON 파일로 보관합니다.
   수치 기준을 통과하고 순위를 계산할 수 있는 모든 후보가 검토 대상입니다. 요청에 붙은
   `prospective` 이름이나 해시만으로 원본 출처가 인증되지는 않습니다.
   새 요청은 schema 2이며, `family_commitment`에 **실패한 후보까지 포함한 전체 원본 수집 파일의
   바이트 해시·재계산 결과 해시·계획 해시**를 함께 묶습니다. 전체 후보 파일을 읽고 계산할 수 없으면
   서명 가능한 선택 요청을 만들지 않습니다. 원본 파일의 서식이나 줄바꿈도 바꾸지 않습니다.
4. 실제 배포 기간의 고정 실행기 명세와 감사 문서를 준비하고,
   [전략 검토 서명 절차](strategy-review-signing.md)에 따라 각 요청에 `review-approve`를 수행합니다.
   최종 코드 승인, 현재 소유자 키, 독립 자료 출처와 게시 시각 확인이 필요합니다.
5. 모든 해당 서명 파일을 아래 명령에 전달합니다. 이 명령은 파일을 쓰거나 서명·활성화·주문을 하지
   않습니다. 실제 소유자 컨텍스트와 현재 공개키를 읽는 작업은 사용자의 Windows 환경에서 이 명령을
   명시적으로 실행할 때만 시작합니다. 키나 로그를 개발 에이전트에게 보낼 필요가 없습니다.

```powershell
& "<TRADEGEN>\.venv\Scripts\python.exe" -m execution_launch.study_review select-reviewed --plan "<개인 자료>\plan.json" --profile "<개인 자료>\profile.json" --captures "<수집 폴더>" --evaluated-at "<원래 평가 시각의 UTC ISO 문자열>" --review "<개인 자료>\candidate-a.signed-review.json" --review "<개인 자료>\candidate-b.signed-review.json"
```

서명 파일 수에 맞춰 `--review`를 반복합니다. 후보가 두 개라는 가정은 예시일 뿐입니다.
서명하지 않은 후보를 일부러 빼서 다른 후보를 고를 수 없도록, 수치상 적격인 모든 후보의 검토를
요구합니다. 수치상 적격 후보가 없다면 `--review` 없이도 결과를 확인할 수 있으며 선정은 일어나지 않습니다.

## 실제로 확인하는 것

- 동결 계획의 전체 후보 수집 파일을 다시 계산합니다. 가져온 통계나 `PASS` 표시는 받지 않습니다.
- 원래 평가 시각으로 결과 해시를 재현합니다. 현재 유효성은 명령 자체의 시계로 확인하며,
  사용자가 전달하는 `--now`로 서명 만료를 우회할 수 없습니다.
- 서명된 요청의 프로토콜·결과·입력·후보군·프로그램·현재 정책과 조건·수치 요약이 다시 계산한 값과
  일치해야 합니다. 원래 평가 시각, 조건, 소스 코드가 바뀌면 서명을 재사용할 수 없습니다.
- 모든 서명에는 동일한 전체 후보군 증거가 들어 있습니다. 높은 순위 후보의 자료를 나중에 불합격처럼
  고치고 그 후보의 서명만 빼거나, 실패한 후보의 자료를 교체하면 다른 후보의 기존 서명도 거부됩니다.
  후보 하나만 묶은 기존 schema 1 서명은 이 명령에서 받지 않으며 자동 승격하지 않습니다.
- 기존 `verify_source_review`로 Ed25519 서명, 현재 키와 코드 승인, 봉인된 소유자 상태, 같은 서울 날짜,
  중지 여부, 30초 이내 컨텍스트, 최대 24시간의 서명 기한을 검사합니다.
- 검토 하나가 잘못됐거나 누락·만료되면 해당 행만 빼고 다른 후보를 선택하지 않고 전체 선택을 거부합니다.
- 기존 유의성·다중검정·비용 두 배·체결 지연·왕복 횟수·낙폭·순위 규칙을 그대로 적용합니다.

`source_reviews_authenticated=true`, `research_review_ready=true`, `selection.status=SELECTED`는 해당
연구의 출처 검토를 인증한 선정 결과입니다. `implementation_authenticated`와 `execution_ready`는 계속 `false`입니다.
고정 실행기와 실시간 이력 연결, 실제 계좌의 기준선과 위험 여유, 현재 거래 조건, 세션 준비와 소유자
활성화는 실행 때 다시 검사합니다. 손실 하한이나 수수료 여유 문제를 이 명령으로 해제하지 않습니다.

현재 경로는 Upbit 원화 현물의 동결된 단일 자산 연구에 한정됩니다. 다중 시장 선택이나 KIS·OKX 연구가
완성됐다고 표시하지 않습니다. 실제 전략 통과나 수익을 보장하지 않습니다.
전체 후보군 요청을 생성하도록 `study.py`와 외부 서명기의 검증 코드가 바뀌었습니다. 기존 수집 중인
연구를 새 코드에 맞춰 소급해서 바꾸지 말고, 최종 버전 검토·코드 승인과 새 사전 등록을 완료해야 합니다.
외부 서명기 복사본도 기존 해시 확인·직접 검토 절차에 따라 갱신합니다.
법률·세무·투자 조언이 아니며 작성자는 면허를 가진 자문가가 아닙니다.
