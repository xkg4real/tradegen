# 새 48시간 전향 연구 초안

2026-11-05 소유자의 연구 단계 단축 승인을 반영한 **새 연구의 개발안**입니다.
48시간은 신속한 첫 관측을 위한 개발 선택이며, 소유자가 구체적으로 지정한
시간이나 충분한 검정력이 입증된 기간이 아닙니다. 결과를 보고 종료 시점을
고르는 방식으로 사용하지 않습니다. 이번 작업에서 실제 자료를 수집하거나
수익, 통과 전략, 실거래 가능일을 산출하지 않았습니다.

기존 7일 계획은 실행 코드의 고정 하한이 아니었습니다. `ForwardProtocol`에
기간과 표본 수가 들어가므로, 평가기나 보호 규칙을 느슨하게 바꾸지 않고 새
초안을 만들 수 있습니다. 이미 공개한 계획, 진행한 캡처, 고정 역사 연구는
그대로 보존합니다. 새 연구가 완료돼도 실거래 허가는 별도입니다.

## 고정할 내용

| 항목 | 새 초안 |
| --- | --- |
| 기간 | 사전에 정한 시작부터 정확히 48시간 |
| 간격 | 300초, 기존 5분 초안만 입력 가능 |
| 표본 | 수익구간 576개, 시작점과 끝점을 포함한 호가 관측 577개 |
| 후보 | 입력 초안의 전체 프로그램을 그대로 유지; 실패 후보도 제거하지 않음 |
| 거래·비용·검정 | 왕복 횟수, 슬리피지, 지연, 블록 길이, 반복 수, seed, alpha, 연구 낙폭 한도를 그대로 유지 |
| 실제 거래 조건 | 기존 `build_study_plan`이 공급된 비공개 프로필의 자본·수수료·상품 조건을 바인딩 |
| 새 식별자 | 입력 초안과 다른 plan ID 및 study ID 필수 |
| 공개 시점 | 새 `commitment.json`을 첫 관측 전에 별도로 공개 |
| 결과 | 평가 전에는 없음; 초안 검증 성공은 전략 검증 성공이 아님 |

기존 평가에는 최소 20회 왕복, 양의 총수익·평균수익, 단순 보유 대비 우위,
전체 후보를 반영한 유의성 검사, 두 배 비용과 추가 한 봉 지연에서도 양의
수익, 연구 낙폭 제한이 계속 적용됩니다. 이 도구는 그러한 설정을 낮추지
않습니다. 예를 들어 기존 블록 길이가 새 표본에 비해 너무 크거나 왕복
횟수가 구조적으로 불가능하면 새 계획 생성 자체가 거절됩니다.

`max_drawdown`은 연구의 수치 필터입니다. 실계좌의 원금·최고점 하한,
일일 손실 한도나 22시 회복 조건을 대신하지 않습니다. 연구 초안의 낙폭
설정을 보존했다는 사실이 그만큼의 실계좌 손실을 허용한다는 뜻은 아닙니다.

## 실행 가능한 초안 생성

`tools.research.prepare_shortened_study`는 오프라인 도구입니다. 다음 두 파일을
비공개 위치에 준비합니다.

1. 현재 결정과 실제 상품 조건이 담긴 `private-profile.json`.
   상품 조건은 전달한 `--now` 시각 기준 5분 이내여야 합니다. 이 도구는
   거래소에서 조건을 읽거나 시각을 새것으로 바꾸지 않습니다.
2. `study freeze`가 받는 형식의 **미실행 초안** `base-draft.json`.
   최상위 필드는 `schema_version`, `plan_id`, `asset`, `risk_group`,
   `template`, `programs`입니다. 기존 프로그램 전체와 검정 조건을 검토해
   둡니다. 5분 간격이며 최소 576구간·48시간 이상인 초안이어야 합니다.

기존 `plan.json`, `commitment.json`, 캡처 파일은 이 도구의 입력 형식이 아니며
거절됩니다. 공개했던 계획에서 필드를 추출해 미실행 초안처럼 제출하지
않습니다. 도구가 확인할 수 있는 것은 입력 형식과 해당 파일의 ID 차이까지입니다.
전체 연구 이력에서 ID가 유일한지, 앞서 관측한 자료와 겹치지 않는지는 독립
검토에서 실제 기록으로 확인해야 합니다.

PowerShell에서 시각과 새 식별자를 명시해 먼저 금액 없는 진단을 실행합니다.
아래 `NEW_*`와 시각은 실제 새 연구에 맞춰 정할 자리표시자입니다.
검토한 checkout에서 그 checkout의 `.venv`를 활성화해 실행하며, 아래 `python`은
해당 환경의 Python을 뜻합니다. 파일 경로는 비공개 위치의 실제 경로로 바꿉니다.

```powershell
python -m tools.research.prepare_shortened_study --profile private-profile.json --draft base-draft.json --now AWARE_ISO_TIME --capture-start FUTURE_AWARE_ISO_TIME --plan-id NEW_PLAN_ID --study-id NEW_STUDY_ID
```

`--capture-start`는 `--now`보다 최소 2분 뒤여야 합니다. 이는 코드의 최소
시작 여유일 뿐이며, 실제 검토·공개·프로그램 시작에 필요한 시간을 따로
확보합니다. `--now`는 호출자가 공급하는 등록 시각입니다. 올바른 시계나
실제 공개 시각을 이 도구가 인증하지 않습니다.

진단의 `draft_valid=true`와 종료 코드 0을 확인한 다음, 같은 명령 끝에
`--emit-draft`를 추가해 JSON을 비공개 파일로 저장합니다. 명시적으로 이
플래그를 넣은 경우에만 전체 초안이 stdout으로 나옵니다. 초안에는 금액이
들어갈 수 있으므로 공개 저장소에 올리지 않습니다. Windows PowerShell 5.1에서는
UTF-16/BOM을 만드는 `>` 대신 ASCII 출력을 그대로 보존하는 다음 방식을 씁니다.

```powershell
python -m tools.research.prepare_shortened_study --profile private-profile.json --draft base-draft.json --now AWARE_ISO_TIME --capture-start FUTURE_AWARE_ISO_TIME --plan-id NEW_PLAN_ID --study-id NEW_STUDY_ID --emit-draft | Set-Content -Encoding ascii new-private-draft.json
if ($LASTEXITCODE -ne 0) { throw 'Draft preparation failed; do not freeze this output.' }
```

그다음 기존 명령을 사용합니다. `NEW_EMPTY_DIR`은 미리 만든 빈 비공개 절대
경로여야 하며, `NEW_CAPTURE_DIR`도 별도로 준비합니다.

```powershell
python -m execution_launch.study freeze --profile private-profile.json --draft new-private-draft.json --out NEW_EMPTY_DIR
```

새 `plan.json`은 비공개로 보관하고 `commitment.json`만 관측 시작 전에
공개합니다. 생성기의 plan 해시는 기존 `freeze`가 생성하는 계획과 같아야
합니다. 그 사이 코드·프로필·입력 파일을 바꿨다면 다시 대조해야 합니다.
시각 진단과 공개 증거를 확인한 뒤에만 소유자가 기존 `study capture`를
실행합니다. 개발 에이전트는 실제 거래소를 호출하지 않았습니다.

## 결과 해석과 재시도

48시간에는 시장 국면과 독립된 시간 블록이 적습니다. 576개 구간은 576개의
독립 표본이라는 뜻이 아니며, 최소 거래 횟수조차 채워지지 않을 수 있습니다.
짧은 자료에서 블록 부트스트랩의 가정이 맞는지, 테스트할 효과 크기에 충분한
검정력이 있는지는 아직 검증되지 않았습니다. 7일도 그 자체로 충분함을
보장하지 않습니다. 기간을 줄이는 승인은 결과를 통과로 바꾸는 승인이 아닙니다.

첫 거부, 누락 슬롯, 중단은 기존 규칙대로 해당 시행을 끝냅니다. 채워 넣기,
중간 결과를 본 뒤 기간 연장, 실패 후보 제외, seed·검정 기준 재조정으로
같은 연구를 구제하지 않습니다. 재시도는 새 계획과 미래 구간으로 등록하고
실패·미완료 시행까지 모두 공개해 선택 편향과 전체 시도 수를 검토합니다.
현재 코드가 자동으로 전 세계 연구 이력의 완전성을 입증하지는 않습니다.

`select`의 기존 명령은 신뢰 가능한 검토자를 연결하지 않아
`NO_QUALIFIED_MARKET`을 유지합니다. 수치 조건을 충족한 후보의 검토 요청,
실제 출처·사전공개·프로그램 검토, 소유자의 `review-approve`가 따로 필요합니다.
새 코드 서명, 계좌 연속 증거, 손실 하한, 세션 및 거래 조건 검사를 우회하지
않습니다. 보유 코인 연속 추적과 실거래 연결 같은 미완료 개발도 그대로 남습니다.

법률·세무·투자 조언이 아닌 개발 및 연구 문서이며, 작성자는 면허 있는
자문가가 아닙니다.
