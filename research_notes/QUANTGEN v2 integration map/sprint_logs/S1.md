## Deviations from the rulings or the spec (with reason)

1. `tree_hash` is an optional property of the five artifact schemas and the third `VOLATILE_FIELDS` entry (ruling 3.1 requires every artifact to write it; the spec's closed objects and `volatile_fields: [generated_at_utc, git_hash]` predate that ruling). Lock before the M7 freeze.
2. Hermetic guard is armed per macro test and restored in `finally`, not patched process-wide at import: a process-wide patch of `data.net.session` breaks `engine/test_82` (loopback HTTPServer) and changes `cockpit/test_21`. T-HERM-01 still holds for every macro test.
3. An owner ruling never rewrites the store: `apply_owner_ruling` appends one `owner_ruling` event; `load_store(path, rulings_log=...)` replays it (status `owner_set`, `effective_from`/`rationale` from the event). This reconciles "store byte-identical" with "status flips".
4. `RuleObject` carries four non-section-7.1 fields: `factor` (F-9 discriminator), `disposition`, `evidence`, `extras` (the "any field" shapes of items 21, 22, 23/32, 24, 35).
5. Cost table lives in `core/quant/validate.COST_BP_PER_SIDE` (per ruling); the tick floor and `cost_per_side` live in `core/quant/instruments.py`, not `core/quant/cards.py` (M7 may re-export). `backtest.py` and `markets.py` untouched.
6. `verify_chain` returns `ChainCheck(ok, n_rows, first_bad_line)` (truthy == ok) rather than a bare bool; `read_events` refuses a broken chain.
7. `validate_card_header(header, store, *, rule, ...)` returns a `Report` (field-addressed issues, the UI convention) instead of raising, and takes the section 7.1 object as `rule=` because the store has no `rules` block (`store.rule()` of brief B6 does not exist). `rule=None` fails closed.
8. `header_checks` check 7 requires `exec_variants_ABC` in `printed_lines` (R-26 rule 6, an M7 clause pre-implemented). The section 8.4 example header lacks it, so committing that header verbatim is refused; M7 adds the six `instruments.printed_lines` names to each header or moves check 7 to the result part.
9. `--milestone M<k>` selects by `test_ids` with registry `runs_from <= M<k>`; the legacy 266 carry no ids and are excluded under `--milestone` (they always run without it).
10. T-RO-01 does not scan the external skills root (`config.skills_root()`); it scans `core/skills/macro_workflows/*.yaml` when present (none yet).
11. Package A's sidecar `tests/fixtures/macro/macro_m0_schemas.fixtures.json` is a listing, not a fixture (excluded from the unlisted-file check); MANIFEST.csv lists the two fixtures with their md5 (dde27bf9..., 88c69369...).
12. TASK-M0-15 (E -> B labels) is REFDATA: labels stay as shipped (27 E labels), reported NOT_RUN under T-DNB-01.
13. D2 non-default `"-1.5*sigma_book"` is accepted as a ruling value; the hard-stop evaluation of that string is R-07's (M5) and must fail closed on it until defined (F-19).

## Gotchas for the next implementers

- Every artifact must carry `tree_hash` (use `provenance()`); builders that start from spec examples overwrite the provenance fields.
- `MacroStore.get` has no defaults: owner-input nulls (`sleeves.*.notional_nav`, `vol_target.other_markets.target_ann`) resolve to `None`; consumers must refuse on `None`.
- Tests write only to tempfile dirs; set `QUANTGEN_MACRO_DIR` to a tempdir when a module reads `config.macro_dir()`; never write under `~/.nextgen`.
- After adding a test with `test_ids`, run `python -m tests.macro_acceptance` to resync `implemented_in`; `test_registry_implemented_in_matches_test_ids` fails otherwise.
- `python -m tests.notrun` prints manifest skeleton rows for unlisted fixtures; the manifest test fails until they are listed with licence, owner and md5.
- Host: the Bash tool fails on heredocs containing an apostrophe (use the Write tool); the console is cp949, run python with `PYTHONIOENCODING=utf-8`.
