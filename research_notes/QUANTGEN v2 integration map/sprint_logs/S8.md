## Gotchas for the next sprint

- `view_shell` / `build_overlay_view` call `refresh()` at build time; with Flet's real `run_thread` the first read races the
  switcher mount harmlessly (the worker sets `host.controls` and calls `page.update()`), but a test stub must run the worker
  synchronously or it sees the "Reading…" state.
- `ft.Button("x")` stores its label in `.content` (a str), not in an `ft.Text`: tree walkers that collect `ft.Text` values miss
  button labels.
- The runner imports every test module at start but UI modules lazily inside tests: never edit `ui/` while a full run is in
  flight.
- Pressing Run in the served app writes the real `~/.nextgen/macro/dry_run/`; the Artifacts selector then defaults to Live only
  when `~/.nextgen/macro/macro_state/` exists.
