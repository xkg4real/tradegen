## Deviations from the rulings or the spec (with reason)

1. **Clocks adapter.** The five calendar methods the data layer consumes live in `core/calendars/adapter.py` (`CalendarClocks`), not in `clocks.py`:
   the adapter needs `publication.py` and the registry, and `clocks.py` must stay a leaf. The registry names each series' schedule id; the signed
   `publication_schedules` row supplies rule, time and tz (`SCHEDULE_IDS` maps the 17 registry ids to the 14 signed schedule ids; LIVE_QUOTE / AS_POSTED /
   DERIVED have no scheduled instant and answer None). Monthly series step by calendar month. `add_publication_bdays` on a market-close schedule steps
   that market's sessions and returns the close-print bound (the stub's reading).
2. **Calendar failures fail closed with a name.** `contracts._calendar_call` turns any calendar exception (`CalendarUnsigned`, `CalendarCoverageError`,
   an unreadable schedule) into `CalendarUnavailable`; `read_input` returns `MissingInput('missing', detail=<message naming the file>)`; `on_input_failure`
   passes `detail` into `FailureAction.sets` so the alert names the calendar (brief F-5). `MissingInput.detail` is a fifth field appended with default `""`.
3. **KIS allowlist is 25 paths**, frozen in `config.KIS_QUOTATION_ALLOWLIST`: the 24 in use plus `/uapi/domestic-stock/v1/quotations/inquire-asking-price-exp-ccn`
   of the owner-run quote-field check (package D). `kis_client.QUOTATION_ALLOWLIST` is the same object. The layered guard (a non-`/uapi/` placeholder such as
   the legacy engine test's `/p` passes) stays as package A left it; tighten when `tests/engine_acceptance.py` names a quotation path.
4. **Fixture generator.** The CSV rows carry `series_id` as the first provenance column (every datum names its series); `pit.check_fixture` reads JSONL stores
   and these CSVs. `calendar_available_at(registry, clocks)` is the injected instant rule; a series with no scheduled instant (AS_POSTED, e.g. BOK_CALL_RATE
   until the owner supplies its ECOS code and calendar) is refused rather than inferred from retrieval. The CLI uses the shipped (unsigned) calendar set and
   therefore refuses until the owner signs; the reference directory is absent anyway.
5. **`display` on an acting series.** A consumer-less acting binding binds every consumer (package A's `resolve_binding`), so a context consumer reading
   `KOSPI_OFFICIAL_CLOSE` is held to the acting rules (`require_session`); context reads of context-bound series are labelled, never fail. Left as designed.
6. Package C's signatures carry `decision_utc` explicitly (ruling 3.11), one position beyond rulings section 4 (`runtime_halt(registry, book_id, cls, reason,
   decision_utc, component=None, series_id=None)`, `runtime_rearm(registry, book_id, mode, decision_utc, operator=None, cleared=None)`); section 4 of the
   rulings should be updated to these forms. `ever_armed(registry, book_id)` is registry-first.
7. Package deviations reported by the implementers and kept: PIT dedupe key excludes `available_at` / `retrieved_at` (a close is never re-stamped);
   KIS daily rows are `vendor_close` until the M1-01 quote-field check is recorded (`primary_sources.KIS: unverified`); a bar row reaching a close-type acting
   read is `MissingInput('provisional_intraday')`; `regime_tags` returns 15 tags (13 R-20 + `short_sale_regime`, `value_up`); `cross_market_usable('HK')` is
   always False; every calendar file carries file-level `signed_off_by / signed_utc / md5` plus the five row fields and a MANIFEST.yaml row; goldens.csv and
   ACQUISITION.csv are manifest-listed registries (refresh their md5 rows after any edit); `golden_tools` raises a third NotRun prefix `PENDING: §9.4 item <n>`.
