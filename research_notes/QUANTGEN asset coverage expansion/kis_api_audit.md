## KQ1. Which read-only endpoints exist in each domain, with exact path and tr_id?

### Takeaway
KIS exposes 199 quotation/reference REST endpoints across eight domains, all callable with only appkey + appsecret + bearer token (no `CANO`), plus 60 websocket feeds. Domestic stock is by far the widest (108 read-only endpoints); ETF/ETN (5), ELW (21), domestic futures/options (9), overseas stock (28), overseas futures/options (20) and exchange-traded bonds (8) are narrower but cover price, daily chart, order book and reference data in every domain.

### Cited Findings
- The repo is organised as `examples_llm/<domain>/<api>/<api>.py` (one-call file) plus `chk_<api>.py` (test with the output column map); folder names are derived from the URL path — [README](https://github.com/koreainvestment/open-trading-api/blob/main/README.md), [docs/convention.md](https://github.com/koreainvestment/open-trading-api/blob/main/docs/convention.md)
- Parsed counts per domain (REST without CANO / REST with CANO / websocket): domestic_stock 108/23/25, etfetn 5/0/1, elw 21/0/3, domestic_futureoption 9/14/20, overseas_stock 28/18/4, overseas_futureoption 20/11/4, domestic_bond 8/7/3, auth 2/0/0 — parse of [examples_llm](https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm) at commit b4e6249
- Every read-only call sends headers `authorization: Bearer <token>`, `appkey`, `appsecret`, `tr_id`, `custtype: P`, optional `tr_cont` for continuation — [examples_user/kis_auth.py `_url_fetch`](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/kis_auth.py)
- Mock (모의투자) tr_ids: the common helper rewrites a leading `T`/`J`/`C` to `V` for mock; quotation tr_ids that start with `F`/`H` are identical in real and mock — [kis_auth.py `_url_fetch`](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/kis_auth.py). Only 19 no-CANO sample files carry an explicit `demo` branch (13 domestic stock, 3 domestic F/O, 3 overseas stock; listed in the tables as "mock: same"); the rest have no demo branch.
- Exact paths and tr_ids: see "Endpoint inventory for QUANTGEN" below (each row links to the sample file it was read from).

### Inferences
- A sample file without a `demo` branch most likely means the endpoint is not offered on the mock server (KIS's own note: "모의투자 계좌는 REST API 호출 제한이 낮습니다" and the demo domain is separate) — inferred from the code structure, not stated per endpoint.
- Paths under `/quotations/`, `/ranking/`, `/finance/`, `/ksdinfo/` are read-only by construction; only `/trading/` paths carry `CANO`. The parse confirms this: no non-`/trading/` file sends `CANO`.

### Gaps
- The KIS portal's per-endpoint pages (apiportal.koreainvestment.com/apiservice) are a JavaScript app and could not be fetched; the FAQ page fetched on 2026-09-25 showed "총 0건". The repository is therefore the sole primary source for paths/tr_ids.
- Live behaviour (HTTP errors for endpoints that need an agreement, exact delays) was not tested.

### Inferences
- Backward paging recipe for date-range endpoints: request `[end−150 calendar days, end]`, take the earliest `stck_bsop_date` returned, set the next `end` to the day before it, repeat. For anchor-date endpoints (`inquire-index-daily-price`, `daily-credit-balance`, overseas `dailyprice`) set the anchor to the earliest date returned.
- Archive depth: KIS documents no floor. The 100-per-call design plus QUANTGEN's working 504-session window implies multi-year daily depth for KRX stocks; assume the same for indices and futures front-month codes but verify per contract (a futures code only exists for its listed life, so long histories need a continuous-contract stitch).

### Gaps
- Row count per call for overseas `dailyprice` and bond daily endpoints is not stated in the samples (UNVERIFIED; probe with one call).
- Maximum look-back of every daily endpoint is undocumented (UNVERIFIED).
- Whether `inquire-daily-fuopchartprice` accepts KTB/USD/gold codes (market code other than `F`/`O`, e.g. commodity market `CF`) is not shown in the sample; the sample only documents `F` and `O` (UNVERIFIED).

## KQ3. Which endpoints need CANO vs. only the app key? Is a derivatives account or overseas agreement needed to QUERY?

### Takeaway
None of the 199 quotation/reference endpoints send an account number; the only identity fields they ever need are appkey/appsecret/token (plus HTS ID for the personal watch-list and condition-search endpoints). The repository shows that separate 8-digit account numbers exist for stock (product 01), domestic derivatives (03) and overseas derivatives (08) accounts and that these are required to trade, but nothing in the official material says a derivatives account or overseas agreement is required merely to query quotes; that remains UNVERIFIED and should be settled with one test call each.

### Cited Findings
- The parse of all 333 samples found `CANO` only in `/trading/` paths (73 files); every `/quotations/`, `/ranking/`, `/finance/`, `/ksdinfo/` file sends none — parse of [examples_llm](https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm)
- Config template keeps distinct account stems: `my_acct_stock` (증권계좌 8자리), `my_acct_future` (선물옵션계좌 8자리), and product suffixes `01` 종합, `03` 국내선물옵션, `08` 해외선물옵션, `22` 개인연금, `29` 퇴직연금 — [kis_devlp.yaml](https://github.com/koreainvestment/open-trading-api/blob/main/kis_devlp.yaml), [README §3.5](https://github.com/koreainvestment/open-trading-api/blob/main/README.md)
- Service prerequisites listed by KIS: "계좌 개설 및 ID 연결 → Open API 서비스 신청 → 앱키/앱시크릿 발급, 모의투자 및 실전투자 앱키 각각 준비" — [README §3.4](https://github.com/koreainvestment/open-trading-api/blob/main/README.md)
- Endpoints that need the HTS ID (`USER_ID`/`user_id`) rather than an account: `intstock-grouplist` (HHKCM113004C7), `intstock-stocklist-by-group` (HHKCM113004C6), `psearch-title` (HHKST03900300), `psearch-result` (HHKST03900400) — [py](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/psearch_title/psearch_title.py), [py](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/intstock_grouplist/intstock_grouplist.py); README notes HTS ID is "체결통보, 나의 조건 목록 확인 등에 사용" — [README](https://github.com/koreainvestment/open-trading-api/blob/main/README.md)
- QUANTGEN's `.env` holds `KIS_APP_KEY`, `KIS_APP_SECRET`, a 2-digit `KIS_ACCOUNT_PD` and no CANO; its four endpoints work in that state — `data/krx/kis_client.py` (local).
- KIS states the mock account has a lower REST call limit and recommends a real account for heavy querying — [README §5](https://github.com/koreainvestment/open-trading-api/blob/main/README.md)

### Inferences
- Because quotation requests carry no account field, the gateway cannot check a derivatives-account or overseas-agreement flag per call unless it does so at the app-key level. The operator's app key was issued against a stock account; the most likely outcome is that F/O and overseas quotes work, but this is exactly the thing to test first (cheap: one `inquire-price` call with `F`/`A01612` and one overseas `price` call with `NAS`/`AAPL`).
- Everything in the OUT OF SCOPE list is unreachable today anyway (no CANO in `.env`), which is consistent with QUANTGEN's read-only rule.

### Gaps
- No official statement was found on whether querying F/O or overseas quotations requires the corresponding account/agreement (UNVERIFIED).
- The current KIS terms on overseas real-time vs delayed quote entitlement (paid 실시간 시세 for US) were not retrievable (portal is JS-rendered).

## KQ4. Real-time websocket feeds — do they add anything a daily app needs?

### Takeaway
KIS's websocket (`ws://ops.koreainvestment.com:21000`, mock `:31000`, approval key from `/oauth2/Approval`) streams ticks, order books, expected prices, program-trade and NAV updates for every domain, capped at 40 registrations in the sample client; for a daily-frequency app it adds nothing the REST endpoints do not already give at the close, and it introduces AES-decrypted binary framing and PINGPONG handling that QUANTGEN does not need.

## KQ5. Can a Korean retail investor buy US spot bitcoin/ether ETFs or CME crypto futures through KIS in 2026?

### Takeaway
No, on both counts as of 2026-09-25. The FSC's January 2024 position that domestic brokers intermediating overseas-listed spot bitcoin ETFs "could violate the Capital Markets Act" is still the operative rule (brokers block new buys), the government's July 2026 plan to amend the Act for a *domestically listed* spot bitcoin ETF is still a proposal, and CME bitcoin/ether futures have been off-limits since the FSC's December 2017 interpretation; KIS has provided CME BTC/ETH (and micro) futures *quotes only* since 2025-10-21.

### Cited Findings
- FSC press reference, 2024-01-12: "국내 증권사가 해외상장된 비트코인 현물 ETF를 중개하는 것은 가상자산에 대한 기존의 정부입장 및 자본시장법에 위배될 소지가 있습니다"; further review promised as the Virtual Asset User Protection Act took effect in July 2024 — [FSC 보도참고 81456](https://www.fsc.go.kr/no010101/81456)
- FSC 보도설명, 2024-01-15: the position on issuing or brokering spot bitcoin ETFs "변화가 없습니다"; claims of a shift from "위법→보류→검토" are "전혀 사실이 아니" — [FSC 보도설명 81467](https://fsc.go.kr/no010102/81467)
- Bitcoin futures via Korean brokers: on 2017-12-06 the FSC ruled bitcoin is not a qualifying underlying asset under Capital Markets Act Art. 4(10) ("합리적으로 가치를 측정할 수 있는지가 중요"), so domestic firms may not intermediate CME bitcoin futures; Shinhan Financial Investment and eBest cancelled seminars and service preparation — [이데일리 2017-12-06](https://edaily.co.kr/News/Read?mediaCodeNo=257&newsId=02437046616155896)
- KIS notice dated 2025-10-21: KIS added CME quotes for Bitcoin (BTC), Ether (ETH), Micro Bitcoin (MBT) and Micro Ether (MET) futures as "합리적인 투자 판단을 위한 보조적인 정보 제공 차원"; "가상화폐선물의 거래를 지원하지 않습니다" — [KIS 공지 45495](https://securities.koreainvestment.com/main/customer/notice/Notice.jsp?cmd=TF04ga000002&num=45495). Consistent with the live master file: `ffcode.mst` (2026-09-25) lists `BTCU26`, `BTCZ26`, `ETHU26`, `ETHZ26`, `MBTU26`, `MBTV26`, `METU26`, `METV26` on exchange `CME` — [ffcode.mst.zip](https://new.real.download.dws.co.kr/common/master/ffcode.mst.zip)
- 2025-11-21: Korean law "prohibits crypto spot ETFs—both domestic issuance and foreign brokerage", yet products such as Grayscale GDLC and Franklin EZPZ slipped through brokers' mobile apps and were halted; FSC: "법 개정 전에는 감독기관이 움직일 수 있는 폭이 크지 않다" — [인베스트조선 2025-11-20](https://www.investchosun.com/site/data/html_dir/2025/11/20/2025112080229.html)
- 2026-07-14: the government's "2026년 하반기 경제성장전략" says the FSC will amend the Capital Markets Act in H2 2026 to allow a domestic spot bitcoin ETF (adding virtual assets to permissible ETF underlyings); the article notes brokers had stopped accepting new purchases of overseas spot bitcoin ETFs after the FSC's 2024 stance — [한국경제 2026-07-14](https://www.hankyung.com/article/2026071450031)
- 2026-07-15: a KRX-commissioned KCMI report sets three prerequisites — legislation naming virtual assets as an underlying, resolving the kimchi premium (letting operators source coins abroad), and a domestic futures market as an AP hedge — and recommends bitcoin first, altcoins later — [아시아경제 2026-07-15](https://view.asiae.co.kr/article/2026071508024489681)
- 2026-09-01: the amendment "remains in the proposal stage"; managers say launch timing is uncertain pending subordinate rules; a lawyer scores progress "50 or more on a 0–100 scale" — [머니투데이 2026-09-01](https://www.mt.co.kr/stock/2026/09/01/2026090116305048771)

### Inferences
- For QUANTGEN this means: no crypto position data will ever come from KIS; the only crypto-linked KIS data reachable read-only are the CME BTC/ETH/MBT/MET futures quotes and bars via the overseas-futures endpoints (`inquire-price`, `daily-ccnl` with `SRS_CD` such as `BTCZ26`, `EXCH_CD` `CME`), which are legitimately useful as a *macro risk indicator* (e.g., a CME basis or a BTC/NDX beta) at daily frequency.
- Even after a domestic spot-ETF law passes, IBIT/FBTC/ARKB/ETHA access through Korean brokers would need a separate change; nothing found suggests that is planned.

### Gaps
- The July 2026 government document itself (경제성장전략) was not fetched; the claim rests on press coverage.
- Whether bitcoin *futures* ETFs (e.g., BITO) remain tradable through Korean brokers was reported in search summaries of the FSC releases but not present in the fetched release text (UNVERIFIED).
- No FSS/FSC document dated 2025–2026 that changes the overseas spot-ETF brokerage stance was found; absence of evidence, not confirmation.

## KQ7. OAuth token rules, request-rate limits, base URLs

### Takeaway
Tokens come from POST `/oauth2/tokenP` (client_credentials + appkey + appsecret), live 24 hours, and KIS throttles issuance to once per minute (error EGW00133 on a repeat); the official samples pace real-account calls at 20/s (mock at 2/s) and EGW00201 signals "초당 거래건수 초과", but the exact official numbers for the mock server are only secondary-sourced.

### Cited Findings
- Base URLs: real `https://openapi.koreainvestment.com:9443`, mock `https://openapivts.koreainvestment.com:29443`; websocket `ws://ops.koreainvestment.com:21000` (mock `:31000`) — [kis_devlp.yaml](https://github.com/koreainvestment/open-trading-api/blob/main/kis_devlp.yaml)
- Token endpoint `POST {base}/oauth2/tokenP` body `{"grant_type":"client_credentials","appkey":…,"appsecret":…}`; response `access_token` and `access_token_token_expired` (datetime); sample stores it in a dated file — [examples_user/kis_auth.py `auth`](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/kis_auth.py), [auth_token sample](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/auth/auth_token/auth_token.py)
- Sample comments: "토큰 유효시간 1일, 6시간 이내 발급신청시는 기존 토큰값과 동일, 발급시 알림톡 발송" (valid one day; a re-request within 6 h returns the same token; every issuance triggers a KakaoTalk notice) — [kis_auth.py](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/kis_auth.py)
- README: "토큰 재발급 - 1분당 1회 발급됩니다" and, under "초당 거래건수 초과 (EGW00201)", "모의투자 계좌는 REST API 호출 제한이 낮습니다 … 연속 호출이 많으면 실전투자 계좌를 권장" — [README §5](https://github.com/koreainvestment/open-trading-api/blob/main/README.md)
- The sample client sleeps `0.05 s` between calls on real (`prod`) and `0.5 s` on mock (`vps`), i.e. designed for 20/s and 2/s — [kis_auth.py `changeTREnv`](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/kis_auth.py)
- Secondary: "접근토큰 is valid for 24 hours but limited to issuing once per minute; calling it per request yields EGW00133 on the second call" — [wikidocs 165185 (search snippet; page returned HTTP 403 on fetch)](https://wikidocs.net/165185); "access_token 발급 (24시간 유효)", "토큰 재발급 1분/1회 제한", "약 20건/초 (실전 기준)", EGW00201 on excess, keep "보수적으로 15건/초 이하" — [수수라이프 가이드 2026-03-25](https://soosoo.life/2026-03-25-%ED%95%9C%EA%B5%AD%ED%88%AC%EC%9E%90%EC%A6%9D%EA%B6%8C_%EC%98%A4%ED%94%88API_KIS_Developers_%EC%99%84%EB%B2%BD%EA%B0%80%EC%9D%B4%EB%93%9C/); "API 호출 유량을 초당 20개로 제한" — [hky035 blog](https://hky035.github.io/web/kis-api-throttling/); mock limit reported as 1/s by one source and 5/s by another — [wikidocs 159296 (search snippets)](https://wikidocs.net/159296); a mock-server rate error also appears as `EGW00215 초당 거래건수 초과` — [FIN-US issue #410](https://github.com/FIN-US/fin-us/issues/410)
- Per-endpoint advice: option board `display-board-callput` "조회시간이 긴 API … 1초당 최대 1건 권장" — [py](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_futureoption/display_board_callput/display_board_callput.py)
- QUANTGEN already caches the token on disk with expiry (`~/.nextgen/kis_token.json`) and refuses to mint one while a cached token is valid — `data/krx/kis_client.py` (local, lines 104–150).

### Inferences
- Real-account pacing of ≤15/s with a token minted at most once per day is safe; a daily app that fetches ~50 instruments × 5 pages is a few seconds of traffic.
- Because a re-issue within 6 h returns the same token, QUANTGEN's cache is mainly protecting against the 1/min throttle and the KakaoTalk noise, not against invalidation.

### Gaps
- Official per-second numbers (real 20/s, mock 2/s) were not confirmed on the KIS portal (FAQ empty on fetch; search budget exhausted). Treat "20/s real" as well-corroborated secondary, "2/s mock" as the sample's pacing only.

## Quant use per domain

Daily or coarser, laptop-runnable, read-only. Each item names the endpoint(s) that make it possible; feasibility of the endpoint is verified, the strategy value is the researcher's inference.

- Domestic stock (KRX/NXT/통합)
  - Cross-sectional momentum, mean reversion and volatility-scaled portfolios on adjusted daily closes: `inquire-daily-itemchartprice` (adjusted flag), paged 100 rows at a time; universe from `market-cap` ranking or the KOSPI/KOSDAQ master files.
  - Flow factors: foreign and institution net buying by investor type (`investor-trade-by-stock-daily`, `inquire-investor`, `inquire-investor-daily-by-market`), program trading pressure (`program-trade-by-stock-daily`, `comp-program-trade-daily`), broker footprints (`inquire-member-daily`, `frgnmem-*`).
  - Positioning / crowding: short-sale ratio and volume (`daily-short-sale`), margin and stock-loan balances (`daily-credit-balance`), securities-lending outstanding (`daily-loan-trans`), market funds (`mktfunds`) — inputs for a short-squeeze or leverage-regime screen.
  - Fundamental value/quality: `/finance/*` (annual or quarterly ROE, margins, leverage, growth), consensus (`estimate-perform`), ratings (`invest-opinion`); event calendars from `/ksdinfo/*` (dividends, rights issues, splits, mergers) for ex-date handling and event studies.
  - Market microstructure at daily granularity: VI trigger counts (`inquire-vi-status`) as a stress indicator; limit-hit lists (`capture-uplowprice`).
  - Calendar: `chk-holiday` and `market-time` remove the need for a hand-maintained KRX holiday list.
  - Domestic rates for the Macro sheet: `comp-interest` (KTB/corporate yields by date) — a KRW leg for the 2s10s and credit-spread indicators that today come only from FRED/OECD.
- ETF/ETN
  - Premium/discount (괴리율) mean reversion and NAV tracking-error monitoring: `nav-comparison-daily-trend` (≤100 rows per call), `inquire-price` (tracking error, LP holdings).
  - Look-through and replication: `inquire-component-stock-price` gives the full basket with weights — enables factor exposure of KRX bond/rates ETFs, and a cheap proxy for the KTB curve via KTB ETF NAVs.
  - Daily prices for ETFs use the stock daily endpoint.
- ELW
  - Implied-volatility surface on KOSPI200 names from listed warrants: `volatility-trend-daily`, `sensitivity-trend-daily`, `udrl-asset-price` — a daily IV time series per underlying for the FX/vol modules' realised-vs-implied studies. Daily frequency is enough; the tick endpoints are unnecessary.
- Domestic futures and options
  - Continuous KOSPI200 / mini / KOSDAQ150 / KRX300 futures series with basis and open interest: `inquire-daily-fuopchartprice` per contract (front month from `월물구분코드`=1 in the master), stitched at roll; basis vs theoretical from the same output.
  - Option surface and Greeks snapshot at the close: `display-board-option-list` (expiries) then `display-board-callput` (one call per expiry; ≤1/s) — feeds a daily implied-vol smile, put-call OI ratio, risk reversal / butterfly in KOSPI200 terms, and a pricing check of QUANTGEN's Black-76 against KIS's theoretical price and Greeks.
  - Rates and FX futures (KTB 3y/5y/10y/30y, KOFR 3M, USD/JPY/EUR/CNH, gold): codes exist in `fo_com_code.mst` (`A65…`, `A67…`, `A70…`, `A69…`, `A75…`); the price/daily endpoints are the same as index futures but the market code for commodity futures is undocumented in the samples — one probe call decides whether the Rates/FX pages can use KTB and USD futures from KIS.
  - Not available read-only: futures investor flows by type (use KRX data marketplace / pykrx instead).
- Overseas stock (US/HK/JP/CN/VN)
  - Daily histories (`dailyprice`), screener (`inquire-search`), reference (`search-info`), corporate actions (`period-rights`, `rights-by-ice`) — a second EOD source next to FMP/yfinance, with the caveat that quotes may be delayed.
  - Macro daily charts via `inquire-daily-chartprice`: US indices (`N` + SPX/COMP/NDX/.DJI/VIX), FX incl. 원/달러 (`X` + FX@KRW), US Treasury yields (`I` + Y0202 etc., mapping UNVERIFIED), COMEX gold (`S` + M0101, UNVERIFIED) — overlaps FRED/yfinance but adds the KRW fixing series the Macro page needs.
- Overseas futures and options (CME/CBOT/NYMEX/COMEX/ICE/EUREX/SGX/HKEx)
